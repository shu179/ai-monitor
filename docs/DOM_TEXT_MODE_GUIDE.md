# DOM文本渲染模式使用指南

## 概述

DOM文本渲染模式是识别模式的增强功能，允许通过**复制文本**而非截图来触发品牌监控。系统会自动将文本渲染为格式化的截图，完美保留markdown排版，并进行品牌识别。

## 核心优势

### 1. 识别准确率 100%
- **纯文本匹配**：直接在文本中搜索品牌词，无OCR误差
- **无AI幻觉**：跳过AI视觉识别，避免误判
- **零信息损失**：直接获取原始文本，无截图压缩损失

### 2. 速度提升 50%+
- **品牌识别前置**：在文本态完成匹配，跳过AI调用
- **端到端延迟**：从3-5秒降至1-2秒
- **成本更低**：无需调用AI视觉API

### 3. 完美排版还原
- **Markdown支持**：标题、列表、表格、代码块、加粗、斜体
- **自动高亮**：品牌词自动添加青色背景
- **专业排版**：使用Inter、Source Han Sans CN等专业字体
- **响应式设计**：最大宽度760px，适配各种屏幕

### 4. 适用场景
✅ 从AI对话页面复制回答内容（最常见）  
✅ 文本密集型内容（文章、对话、文档）  
✅ 需要保留markdown格式的内容  
✅ 对识别准确率要求极高的场景  

❌ 需要识别图片中的文字（如截图、照片）  
❌ 需要保留原始视觉效果（颜色、字体、布局）  
❌ 用户习惯截图而非复制文本  

## 配置方法

### 1. 启用DOM文本渲染模式

编辑 `config.yaml`：

```yaml
recognition:
  # 基础配置
  safe_mode_ocr_enabled: true
  poll_interval_seconds: 1.2
  
  # DOM文本渲染模式（新增）
  dom_render_mode: true                    # ✅ 启用文本监听模式
  dom_render_default_platform: "deepseek"  # 默认平台logo（可选）
  dom_render_min_length: 10                # 最小文本长度（避免误触发）
  dom_render_max_length: 50000             # 最大文本长度（避免渲染超大文本）
```

### 2. 配置说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `dom_render_mode` | boolean | `false` | 是否启用文本监听模式（而非截图监听） |
| `dom_render_default_platform` | string | `""` | 默认平台标识，用于显示logo（如"deepseek"、"kimi"等），留空则显示"AI" |
| `dom_render_min_length` | integer | `10` | 最小文本长度，少于此长度的文本会被跳过 |
| `dom_render_max_length` | integer | `50000` | 最大文本长度，超过此长度的文本会被跳过 |

## 使用方法

### 1. 启动应用

```bash
python3 main.py
```

### 2. 切换到识别模式

在系统托盘图标中选择"识别模式"。

### 3. 复制文本

从AI对话页面（如DeepSeek、Kimi、豆包等）复制包含品牌词的回答内容：

- **macOS**: `Cmd + C`
- **Windows**: `Ctrl + C`

### 4. 自动处理流程

系统会自动执行以下步骤：

```
1. 检测到剪贴板文本变化
   ↓
2. 文本长度检查（10-50000字符）
   ↓
3. 文本品牌匹配（纯文本正则匹配，<10ms）
   ↓
4. 如果匹配到品牌 → 渲染为格式化截图（1-2秒）
   ↓
5. 跳过AI识别（已在文本态完成）
   ↓
6. 路由到对应任务批次
   ↓
7. 发送企业微信通知
```

### 5. 查看结果

- **日志输出**：
  ```
  [Recognition] 文本已识别品牌 ['DeepSeek', 'Kimi']，截图已渲染: text_0422_143025_abc12345.jpg
  [Recognition] 使用文本匹配结果: ['DeepSeek', 'Kimi']
  ```

- **截图文件**：`screenshots/recognition/text_*.jpg`
- **企业微信通知**：自动发送到配置的webhook

## 工作原理

### 截图模式 vs 文本模式

| 对比项 | 截图模式（原有） | 文本模式（新增） |
|--------|-----------------|-----------------|
| 触发方式 | 复制截图 | 复制文本 |
| 识别方式 | OCR + AI视觉 | 纯文本匹配 |
| 准确率 | 95-98% | 100% |
| 延迟 | 3-5秒 | 1-2秒 |
| 成本 | 需要AI API | 无需AI API |
| 排版保留 | 依赖OCR | 完美保留 |
| 适用场景 | 图片、UI界面 | 文本内容 |

## 常见问题

### Q1: 为什么文本没有被识别？

**可能原因：**
1. `dom_render_mode` 未设置为 `true`
2. 文本长度不在范围内
3. 文本中不包含任何配置的品牌词
4. 文本与启动时的剪贴板内容相同（被去重）

### Q2: 如何切换回截图模式？

设置 `config.yaml`：

```yaml
recognition:
  dom_render_mode: false  # 切换回截图模式
```
