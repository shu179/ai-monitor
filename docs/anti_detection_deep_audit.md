## 一、发现的关键问题

### 🔴 严重问题

#### 1. **无头模式的检测风险**（高风险）

**问题描述**:
```python
# platforms/base.py:280
headless=(not self.inspect) and (not self.always_headed)
```

**风险分析**:
- 除了百度文心（`always_headed=True`），其他5个平台都使用**无头模式**
- 无头模式即使有 Patchright 保护，仍然存在检测风险：
  - `window.outerWidth/outerHeight` 可能为 0（已有JS修复，但不够）
  - `navigator.plugins.length` 可能为 0（已删除伪造，依赖Patchright）
  - 某些CSS媒体查询可以检测无头模式
  - 浏览器行为差异（渲染速度、事件触发时机）

**中国AI平台的实际情况**:
- 豆包、Kimi、通义千问等平台**反爬策略较强**
- 长期使用无头模式可能被识别为自动化工具
- 百度已经强制有头模式，说明无头模式确实有风险

**建议修复**:
```python
# 建议：所有平台都使用有头模式（最小化窗口）
always_headed = True  # 对所有平台启用
```

**理由**:
1. 有头模式更接近真实用户
2. 最小化窗口不影响后台运行
3. 百度已经验证了这个策略的必要性
4. 性能损失可以接受（长期稳定性更重要）

---

#### 2. **窗口尺寸固定化风险**（中高风险）

**问题描述**:
```python
# platforms/base.py:282, 1081
viewport={"width": 1280, "height": 1600}  # 固定尺寸
window_size="1440,900" if (有头) else "1280,1600"  # 固定尺寸
```

**风险分析**:
- 所有账号使用**完全相同的窗口尺寸**
- 真实用户的窗口尺寸是多样化的（不同显示器、不同习惯）
- 固定尺寸是明显的自动化特征
- 与指纹配置中的 `screen_width/screen_height` 不一致

**实际问题**:
```python
# browser_fingerprint.py 生成的屏幕分辨率是随机的：
screen_resolutions = [(1920, 1080), (2560, 1440), (1440, 900)]

# 但实际窗口尺寸是固定的：
viewport = {"width": 1280, "height": 1600}  # 所有账号都一样！
```

**建议修复**:
```python
# 从指纹配置读取窗口尺寸，确保一致性
screen_width, screen_height = self._fingerprint.get_screen_resolution()
viewport = {
    "width": screen_width, 
    "height": screen_height - 100  # 减去任务栏高度
}
window_size = f"{screen_width},{screen_height - 100}"
```

#### 3. **轮询间隔过于规律**（中风险）

**问题描述**:
```python
# platforms/base.py:2809, 2820
self._cooperative_sleep(1)  # 固定1秒轮询
```

**风险分析**:
- 等待AI回答时，每隔**固定1秒**轮询一次
- 真实用户不会如此精确地每秒刷新
- 固定间隔是机器人的典型特征
- 长时间运行会形成明显的流量模式

**建议修复**:
```python
# 使用随机间隔
poll_interval = random.uniform(0.8, 1.5)  # 0.8-1.5秒随机
self._cooperative_sleep(poll_interval)
```

### 🟡 中等问题

#### 4. **HTTP 头部缺失 Referer**（中风险）

**问题描述**:
```python
# platforms/base.py:1084-1095
"extra_http_headers": {
    "Accept-Language": accept_language,
    "Accept": accept_header,
    # ... 缺少 Referer
}
```

**风险分析**:
- 真实用户在页面内导航时会携带 `Referer` 头
- 缺少 `Referer` 可能被识别为直接访问（不自然）
- 中国AI平台可能检查 `Referer` 来判断流量来源

**建议**:
- Playwright 会自动处理 `Referer`，无需手动设置
- 但需要确保页面导航是自然的（不要直接 `goto` 跳转）

---

#### 5. **行为模拟时机不当**（低风险）

**问题描述**:
```python
# platforms/base.py:311-312
# 移除：不在启动时做行为模拟（此时页面可能还是空白/登录页）
# 真实用户不会在空白页面上滚动，应该在实际使用时才模拟行为
```

**风险分析**:
- 启动时不做行为模拟是对的
- 但在**查询前**也没有行为模拟
- 真实用户在输入前通常会：
  - 浏览页面
  - 移动鼠标
  - 滚动查看历史对话

**建议**:
```python
# 在 type_like_human 之前，偶尔做一次轻量行为模拟
if random.random() < 0.3:  # 30% 概率
    self._simulate_human_behavior()
```

#### 6. **Canvas 噪声注入可能失效**（低风险）

**问题描述**:
```python
# platforms/base.py:720-760
# Canvas 噪声注入概率：0.1%
if (Math.random() < 0.001) {
    imageData.data[i] = Math.max(0, Math.min(255, ...));
}
```

**风险分析**:
- 0.1% 的概率太低，可能完全不生效
- 如果平台多次采样 Canvas 指纹，可能发现完全一致（可疑）
- 但过高的概率会影响渲染质量

**建议**:
- 保持当前策略（0.1%）
- 但增加尺寸限制检查（已实现）
- 监控是否有 Canvas 指纹检测

### 🟢 低风险但可优化

#### 7. **Chrome 版本更新策略**（维护问题）

**问题描述**:
```python
# browser_fingerprint.py:40-41
# Chrome 版本（2026年4月最新稳定版：147）
chrome_major = 147
```

**风险分析**:
- Chrome 每6周发布一个新版本
- 2026年4月是 147，到5月底就是 148
- 长期不更新会暴露"过时浏览器"特征

**建议**:
- 每月检查 Chrome 版本
- 或者使用动态版本检测（从系统 Chrome 读取）

#### 8. **指纹配置的时效性**（维护问题）

**问题描述**:
```python
# browser_fingerprint.py:50-56
# 2026年4月，主流版本是 macOS 14.x 和 15.x
mac_major = random.choice([14, 15])
```

**风险分析**:

## 二、实战场景分析

### 场景1：长期运行（30天+）

**风险点**:
1. ✅ 指纹稳定性 - 已解决（每个账号独立稳定指纹）
2. ⚠️ 无头模式检测 - **高风险**（建议改为有头）
3. ⚠️ 固定窗口尺寸 - **中高风险**（建议随机化）
4. ⚠️ 固定轮询间隔 - **中风险**（建议随机化）
5. ✅ 行为模拟多样性 - 已解决（4种模式）

### 场景2：多账号并发

**风险点**:
1. ✅ 账号隔离 - 已解决（独立 user_data_dir）
2. ⚠️ 窗口尺寸相同 - **高风险**（所有账号1280x1600）
3. ✅ 指纹多样性 - 已解决（每个账号随机生成）
4. ⚠️ 行为模式相似 - **中风险**（虽然有4种，但概率分布固定）

### 场景3：平台封禁应对

**当前机制**:
1. ✅ 人工干预检测 - 已实现（验证码自动暂停）
2. ✅ 错误重试机制 - 已实现（最大5次）
3. ⚠️ 封禁后恢复 - **缺失**（没有账号轮换机制）

**建议**:
- 实现账号池轮换（一个账号被封，自动切换到备用账号）
- 记录封禁历史，避免重复使用被封账号
