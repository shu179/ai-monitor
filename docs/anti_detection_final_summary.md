## 一、修复总览

### 已完成的关键修复

#### 1. ✅ 窗口尺寸随机化（高优先级）

**问题**: 所有账号使用固定的 1280x1600 窗口尺寸，明显的自动化特征

**修复**:
```python
# platforms/base.py:266-283, 1073-1082
# 从指纹配置读取窗口尺寸，确保每个账号不同且与 screen 一致
screen_width, screen_height = self._fingerprint.get_screen_resolution()
window_height = screen_height - (28 if sys.platform == "darwin" else 40)
viewport = {"width": screen_width, "height": window_height}
window_size = f"{screen_width},{window_height}"
```

**效果**:
- 每个账号窗口尺寸不同（1920x1080、2560x1440、1440x900等）
- 与指纹配置中的 screen 分辨率完全一致
- 消除了固定尺寸的自动化特征

---

#### 2. ✅ 轮询间隔随机化（高优先级）

**问题**: 等待AI回答时，固定每1秒轮询一次，机器人特征明显

**修复**:
```python
# platforms/base.py:2807-2811, 2867-2871, 2819-2822
# 使用 0.8-1.5 秒随机间隔
poll_interval = random.uniform(0.8, 1.5)
self._cooperative_sleep(poll_interval)
```

**效果**:
- 轮询间隔不再固定
- 更接近真实用户的不规律刷新行为
- 消除了精确1秒的机器人特征

---

#### 3. ✅ 查询前行为模拟（中优先级）

**问题**: 输入关键词前没有任何浏览行为，不像真实用户

**修复**:
```python
# platforms/base.py:3867-3872
# 30% 概率在输入前模拟浏览行为
if random.random() < 0.3:
    try:
        self._simulate_human_behavior()
    except Exception as e:
        print(f"[{self.name}] 输入前行为模拟失败: {e}")
```

**效果**:
- 30% 的查询会先浏览页面（鼠标移动、滚动）
- 更符合真实用户的使用习惯
- 行为模式更加多样化

## 二、未修复项（需要用户决策）

### ⚠️ 无头模式 vs 有头模式

**当前状态**:
- 百度文心：有头模式（`always_headed = True`）
- 其他5个平台：无头模式

**风险分析**:
- 无头模式存在检测风险（即使有 Patchright 保护）
- 百度已经强制有头模式，说明无头模式确实有风险
- 但有头模式会占用更多资源

**建议**:
```python
# 如果追求最高安全性，建议所有平台都启用有头模式
# platforms/doubao.py, deepseek.py, kimi.py, yuanbao.py, tongyi.py
always_headed = True
```

**决策权交给用户**:
- 如果资源充足，建议启用全平台有头模式
- 如果资源有限，可以保持当前配置（无头模式）
- 可以先观察无头模式的效果，如果频繁触发验证码再改为有头
